# Отчёт о тестировании: интернет-магазин Toolshop

## 1. Итог

Протестированы ключевые сценарии магазина: регистрация, вход, каталог, поиск, корзина,
оформление заказа. Найдено **48 дефектов**, из них **3 критичных**. Регресс автоматизирован:
**102 автотеста** и коллекция Postman выполняются в CI на каждое изменение, полный цикл
вместе с подъёмом окружения занимает около 5 минут.

**Главные риски для выпуска:**
1. Пользователь может потерять доступ к аккаунту после смены или сброса пароля (версия with-bugs).
2. Заказ можно оформить служебным способом оплаты без реальной оплаты (версия with-bugs).
3. Если сервер отклоняет заказ, сайт не сообщает об этом пользователю (L-07, и в версии без намеренных багов).
4. Проверки данных на сервере неполные: не проверяется формат email, обходится лимит количества
   в корзине, граница возраста 93 года вместо 75 (версия без намеренных багов).

### Замер ручного регресса

Выборка — 12 кейсов, по два из каждого модуля, в основном High. Каждый кейс выполнялся вручную
на `localhost:4200` с секундомером: старт — первое действие кейса, стоп — вынесен вердикт
«прошёл / не прошёл». Подготовка (запуск окружения, заранее созданный аккаунт) в замер не входила.

| Кейс | Время |
|---|---|
| TC-AUTH-06 Вход | 0:10 |
| TC-AUTH-07 Вход с неверным паролем | 0:08 |
| TC-REG-01 Регистрация | 1:22 |
| TC-REG-11 Пароль без цифры | 1:20 |
| TC-CAT-16 Поиск | 0:04 |
| TC-CAT-19 Сортировка по цене | 0:04 |
| TC-CART-13 Счётчик корзины | 0:06 |
| TC-CART-15 Цена строки в корзине | 0:05 |
| TC-CHK-01 Оформление заказа | 0:12 |
| TC-CHK-03 Неверные данные карты | 0:16 |
| TC-CON-01 Сообщение с вложением | 0:09 |
| TC-CON-02 Список тем | 0:06 |
| **Итого / среднее** | **4:02 / 0:20 на кейс** |

72 кейса × 20 секунд ≈ **24 минуты** чистого выполнения. Реальный ручной регресс дольше:
сюда не входят подготовка тестовых данных, сброс окружения и оформление результатов.
Больше всего времени занимают формы с большим числом полей — регистрация (треть всего замера).

**Сравнение:** автоматический регресс — 35 секунд на 102 автотеста в CI (около 5 минут вместе
с подъёмом окружения), и он выполняется без участия человека на каждое изменение.

## 7. Что не тестировалось

- Нагрузка и безопасность — публичный стенд нагружать нельзя. Исключение — проверка устойчивости
  поиска к SQL-инъекции и длинным строкам.
- Админ-панель, отчёты, избранное, аренда инструментов.
- Мобильная вёрстка и браузеры, кроме Chromium.

## 8. Проблемы окружения и выводы

Подробно — в [notes.md](notes.md). Главное:
- тесты должны работать в контролируемом окружении: публичный стенд закрыт защитой от ботов,
  поэтому магазин поднимается в Docker локально и в CI;
- готовность окружения нужно проверять по-настоящему: в CI тесты падали, потому что стартовали
  раньше, чем магазин был готов;
- «работает у меня, но не в CI» — значит, окружения различаются (права на файлы на Windows и Linux);
- падающий тест нельзя «чинить», ослабляя проверку: 404 вместо 422 в Postman оказался
  отсутствующим заголовком `Accept: application/json`, а не особенностью сервера.
