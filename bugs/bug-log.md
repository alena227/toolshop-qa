# Журнал найденных дефектов

Быстрый журнал всех находок: одна строка на каждую. Подробные баг-репорты по самым
серьёзным заведены в [GitHub Issues](https://github.com/alena227/toolshop-qa/issues)
по форме баг-репорта — ссылка на issue стоит в колонке «Статус».

**Окружения**
- **with-bugs** — https://with-bugs.practicesoftwaretesting.com (версия с намеренными багами)
- **local** — `http://localhost:4200`, Docker, `sprint5` (версия без намеренных багов)

**Статусы:** 📝 записан · 🔍 нужна проверка · ✅ оформлен баг-репорт

**Скриншоты** кладу в `bugs/screenshots/` с именем по ID, например `W-15.png`.

## Версия без багов (local, sprint5)

| ID | Область | Что не так | Severity | Статус |
|---|---|---|---|---|
| L-01 | Регистрация | Если сервер отвечает ошибкой без тела и CORS-заголовков (500), вместо понятного сообщения показывается текст `true`. Причина в коде: `register.component.ts` склеивает поля объекта `ProgressEvent`, единственное его поле — `isTrusted: true` | Minor | 📝 |
| L-02 | Регистрация, API | В день 18-летия регистрация отклоняется: «Customer must be 18 years old.» Найдено автотестом `test_register_with_valid_age[18-exact]`. Причина: строгое правило `before:` (дата должна быть раньше «сегодня − 18 лет», а не «не позже») | Minor | 📝 |
| L-05 | Регистрация, API | Сервер принимает email в любом формате: `qa123.example.com` (без @), `qa123@` (без домена), `@x.example.com` (без имени), с пробелом, с двумя @ — все регистрируются (201). Найдено автотестом `test_register_with_invalid_email_format`. Причина: в правилах валидации поля email нет проверки формата (`email`) | Major | 📝 |
| L-06 | Корзина, API | Лимит «не больше 99 штук» обходится повторным добавлением: 99 + 1 = 100, три раза по 99 = 297 штук одного товара в корзине. При этом `PUT /carts/{id}/product/quantity` со значением 100 отклоняется (422). Ограничение проверяет одну операцию, а не итоговое количество. Найдено автотестом `test_adding_product_again_cannot_exceed_quantity_limit` | Major | 📝 |
| L-07 | Оформление заказа, UI | Если сервер отклоняет заказ, сайт молчит: после «Payment was successful» нажатие Confirm отправляет `POST /invoices` → `422`, но на экране ни подтверждения, ни сообщения об ошибке. Пользователь застревает на шаге оплаты и не понимает, что заказ не создан. Воспроизводится с адресом Moscow / RU / 101000 из профиля | Major | 📝 |
| L-08 | Регистрация ↔ оформление заказа, API | Проверки адреса противоречат друг другу: регистрация принимает адрес Moscow / RU / 101000, а оформление заказа отклоняет тот же адрес из профиля (`billing_country: The city does not belong to the selected country`). Сервер сверяет город со справочником индексов, который возвращает выдуманные города (для 101000 — «Воскресенск»), а при регистрации такой сверки нет | Major | 🔍 |
| L-04 | Регистрация, API, производительность | `POST /users/register` отвечает от 3 до 11+ секунд (замеры автотестом с `--durations`), из-за чего автотесты с таймаутом 15 с периодически падали. Вероятные причины по логам: отправка письма при регистрации и проверка пароля по базе утечек через внешний сервис. Таймаут в тестах поднят до 30 с (`API_TIMEOUT`), но время ответа стоит обсудить как требование | Minor | 🔍 |
| L-03 | Регистрация, API | Верхняя граница возраста не 75, а 93 года: регистрация с возрастом 75 лет и 1 день проходит. Найдено автотестом `test_register_with_invalid_age[75-plus-1-day]`. Причина: `Carbon::subYears()` меняет сам объект, поэтому `subYears(75)` вычитается из уже уменьшенной на 18 лет даты | Major | 📝 |

## Нужна проверка

| Что | Как проверить |
|---|---|
| Счётчик количества на странице товара | Нажать «+» до 3 → меняется ли число в поле? Нажать «Add to cart» → на сколько вырос значок корзины (1 или 3)? Какое количество в самой корзине? |
| Приветствие на странице Contact выводит «Hello al Al» — похоже, сначала фамилия, потом имя | Зарегистрировать пользователя Anna / Smirnova и посмотреть приветствие |
| Вложения на Contact (W-25, W-26, W-27) | Загрузить по одному файлу: `.pdf`, `.jpg`, `.txt` и пустой `.txt` (0 КБ). Для каждого записать сообщение на экране и ответ сервера в DevTools → Network. Сохранить скриншоты |
| «Product already in your favorites list» ×3 (скриншот `W-34-check.png`) | Взять товар, которого точно нет в избранном (проверить My favorites), нажать «Add to favourites» один раз. Если сразу «уже в избранном» — баг. Отдельно: одно нажатие даёт три одинаковых уведомления (как и в W-11) |
| Ошибка суммы в корзине (W-23) | Найти минимальный набор товаров, на котором сумма расходится. Проверить с количеством 2–3 у одного товара |
| Индикатор силы пароля (local) | 1) Вводить пароль по одному символу: не отстаёт ли оценка на один символ? 2) Вставить пароль через Ctrl+V и через автозаполнение: обновляется ли индикатор? |
